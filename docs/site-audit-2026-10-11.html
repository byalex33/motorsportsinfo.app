Security

SEC-1

Anyone can make the alerts cron send requests to any URL

HighEffort S
Fact

The push endpoint is validated only as "an https URL". POST /api/push/subscription has no rate limit, so anyone can register endpoints like https://victim.example/hook. Every minute the alerts cron calls webpush.sendNotification on each matching row.

Why

Your functions become a scheduled outbound POST source for whoever registers. A fake endpoint that answers 201 never fails, so it is never pruned, and loadSubscriptions reads every row on every run. A script can grow the table until the 60-second cron times out and real reminders stop.

Fix

Accept only the browser push services, and add a Vercel Firewall rate-limit rule on /api/push/subscription (for example 10 requests a minute per IP).

// src/server/alerts/validation.ts
const PUSH_HOSTS = [
  /^fcm\.googleapis\.com$/,               // Chrome, Edge (Chromium), Samsung, Opera
  /(^|\.)push\.services\.mozilla\.com$/,  // Firefox
  /^web\.push\.apple\.com$/,              // Safari, iOS Home Screen apps
  /\.notify\.windows\.com$/,              // legacy Edge / WNS
];
const pushEndpoint = httpsUrl.refine(
  (v) => PUSH_HOSTS.some((re) => re.test(new URL(v).hostname)),
  "Unknown push service",
);

SEC-2

PDF.js has a high-severity advisory and renders every FIA Document

HighEffort M
Fact

pdfjs-dist@5.7.284 is inside the range of GHSA-hq66-cqwq-w95j (arbitrary JavaScript when a malicious PDF is opened; fixed in 6.2.108). npm audit flags it.

Why

The relay only serves files from the FIA's decision-document folder, which keeps the risk low. It still means the site's safety depends on nothing malicious ever landing on fia.com, and the viewer runs on your origin, next to the push subscription.

Fix

Upgrade to pdfjs-dist@6.4.299. It is a major bump: re-check getDocument, page.render({ canvas }) and TextLayer against the 6.x API, then open a few long documents (classifications, entry lists) in both themes.

Where
package.json, src/components/documents/pdf-viewer.tsx, src/components/documents/pdf.worker.ts
SEC-3

No security headers beyond HSTS

MedEffort S
Fact

Live responses for / and /f1 carry strict-transport-security: max-age=63072000 and nothing else: no CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy or frame protection.

Why

The site can be framed for clickjacking (the Alerts page asks for notification permission), and there is no backstop if a script injection ever lands.

Fix

Add headers in next.config.ts (the Next 16 guide is at node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md). Ship the CSP as report-only for a week, then enforce it.

async headers() {
  return [{ source: "/:path*", headers: [
    { key: "X-Content-Type-Options", value: "nosniff" },
    { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
    { key: "Permissions-Policy", value: "camera=(), microphone=(), geolocation=()" },
    { key: "Content-Security-Policy-Report-Only", value: [
      "default-src 'self'",
      "script-src 'self' 'unsafe-inline'",
      "style-src 'self' 'unsafe-inline'",
      "img-src 'self' data: blob: https://tilecache.rainviewer.com https://tiles.openfreemap.org",
      "connect-src 'self' https://collect.tracwell.app https://api.rainviewer.com https://tiles.openfreemap.org",
      "worker-src 'self' blob:",
      "frame-ancestors 'none'",
    ].join("; ") },
  ]}];
}

Once www is sorted (SEO-1), extend HSTS with includeSubDomains; preload.

SEC-4

Anyone can drain the Rainbow.ai tile cap

MedEffort S
Fact

parseForecastTile accepts a tile near any of the 67 circuits in CIRCUITS, for any snapshot in the last two hours, every offset and every zoom in range. Each new combination is a counted upstream fetch.

Why

A short script can walk that space and spend the 30,000-tile month. The cap fails closed, so there is no bill, but the forecast radar quietly drops back to RainViewer's past frames for everyone until the 1st.

Fix
  • Accept only tiles near the F1 Featured Round's circuit (the radar is F1-only).
  • Accept only the latest snapshot (and the previous one, for viewers mid-session).
  • Add a Firewall rate limit on /api/radar/tiles/*.

Privacy

PRV-1

Analytics stores a persistent ID without consent, and the privacy text says otherwise

HighEffort S
Fact

Tracwell is created with collectionMode: "product" and consent: "granted". On the live site this writes tracwell:tw_live_…:identity with an anonymousId to localStorage on first visit. Tracwell's own README says product mode persists identity and to "configure consent before collection where required".

The About page says preferences "are never sent to us", but the series_selected, timezone_mode_changed and units_changed events send exactly those choices.

Why

Storing an identifier for analytics needs consent under the EU ePrivacy rules, and the UK only exempts analytics with clear information and an easy opt-out. A privacy promise that doesn't match the code is the bigger reputational risk for a fan site.

Fix

The site never calls identify(), so collectionMode: "private" loses only returning-visitor counts and needs no banner. Then rewrite the Analytics bullet on About to say which choices are counted.

// src/lib/analytics.ts
const client = createTracwell({
  projectKey: TRACWELL_PROJECT_KEY,
  collectionMode: "private", // nothing written to the device
  respectDoNotTrack: true,
});
Where
src/lib/analytics.ts:62, src/app/about/page.tsx:151

Reliability & ops

OPS-1

Schedule Flags are written and never read

MedEffort M
Fact

schedule_flags is described as "something a human should look at" (a Session vanished, an unknown Circuit, a failing source). Only the sync reads it, to resolve old flags. source_checks.lastError is the same. Nobody is told.

Why

A source that breaks mid-season (a redesigned fiaformula2.com page) shows a stale schedule until someone happens to look at the database.

Fix

A daily digest: push to your own subscription, or email, when there are open flags or a Series hasn't synced successfully in 24 hours. A CRON_SECRET-protected /api/status JSON also works with an uptime monitor.

Where
src/server/schedule/sync.ts:104, src/db/schema.ts:72
OPS-2

No CI

MedEffort S
Fact

There is no .github/workflows. The 415 tests, typecheck and lint only run when someone remembers. Vercel builds previews but doesn't run the tests.

Fix

One workflow on pull requests and pushes to main: npm ci, npm run typecheck, npm run lint, npm test. Under a minute today.

OPS-3

No error page

LowEffort S
Fact

There is no app/error.tsx or app/global-error.tsx. With a database, a failed schedule read throws by design, and a cold cache then shows Next's unbranded error screen.

Fix

Add an error.tsx in the style of the 404 ("Red flag"), with a retry button, the Series list and a link to the calendar feed.

OPS-4

The alerts cron reads every subscription every minute

LowEffort M
Fact

runAlerts loads all push_subscriptions rows before checking whether anything is due, then loops subscriptions × Sessions. There are no secondary indexes (sessions.starts_at, schedule_changes.notified_at, fia_documents.notified_at).

Fix

Fine at today's size. Before it grows: load subscriptions only when there are due Sessions, changes or documents; filter followers in SQL on the follows jsonb; add the three indexes in a migration.

The home page is a modal over an empty page

MedEffort M
Fact

The visible page is the Series picker dialog. The h1 and the Series links are sr-only. A first-time visitor gets no close button; a returning one finds that ✕ navigates to their last Series rather than closing anything.

Why

The domain's strongest URL carries almost no visible content, and the site has no answer to the question most fans actually ask: what's on this weekend?

Render the full SeriesPicker (the non-compact version already exists) as the page, with each row showing that Series' Featured Round and its next Session in Viewer Time. Keep the header switcher as the dialog.

SEO-3

Document and telemetry pages answer 200 for missing items

LowEffort M
Fact

Known and commented in the code: the shell streams before params are read. Both pages are noindex, so search is unaffected, but link checkers, uptime monitors and the CDN treat them as success.

Fix

Telemetry slugs are a small known set: validate them before streaming, as the Series route does with ensureStatic. Document numbers (SPL-1) can be validated the same way.

SEO-4

Uppercase Series URLs 404

LowEffort S
Fact

/F1 returns 404. People type /F1, /WEC and /MotoGP, and other sites link that way.

Fix

Permanent redirects for the case variants of the seven Series ids in vercel.ts, or one lowercase rule in a proxy.

LowEffort S

Each Series' lastModified is renderedAt, the time the cache last re-rendered, not the time the schedule changed. Google learns to ignore a lastmod that always moves.

Fix

Use the newest updated_at across the Featured Round and its Sessions (or the newest FIA Document time).

03Method & limits

What was done
  • Read the app routes, API routes, server modules, service workers and key client components.
  • Ran typecheck, lint, the test suite, a production build, npm audit and npm outdated.
  • Probed the live site with curl: status codes, headers, cache state and payload sizes on every route type.
  • Walked the live site in a browser at desktop and 375 px, in light and dark, checking headings, hit targets, spoilers and storage.
What wasn't
  • No Lighthouse or PageSpeed scores: the public PageSpeed API quota was exhausted. Payload sizes stand in.
  • No live push test: the browser used blocks notifications.
  • No load testing of the crons or relays.
  • The privacy and terms points are a developer's reading, not legal advice.
